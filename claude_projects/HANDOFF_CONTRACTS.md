# HYPOLAB hand-off contracts (agent pack v3, HYPOLAB 1.10.3)

The "agents" are Claude chats (three Claude Projects and one scheduled task) with fixed instructions. They cannot
see HYPOLAB or each other: Zacc copies every message by hand. These are the formats that cross each paste, and what
HYPOLAB does with them. If HYPOLAB changes a parser, this file, the prompts and the tests change together.

| Message | From | To | HYPOLAB box |
|---|---|---|---|
| BRIEF / SHORTLIST | Scout & Writer | `briefs.md` (Zacc) | - |
| SOURCE | Ideas app, Leads > From outside > Copy for Scout & Writer | Scout & Writer | - |
| CARD | Scout & Writer, daily brief | Ideas app, Drafts > Import | parsed and checked |
| Critic copy | Ideas app, draft > Copy for the Critic | Critic | - |
| VERDICT | Critic | Ideas app, the draft's verdict box | parsed, stored as advice |
| DIGEST | Ideas app, Week page | Weekly Reviewer | - |
| PLAN | Weekly Reviewer | Ideas app, Week page > The Reviewer's plan | parsed, saved; lessons and dead ends to the journal |
| State text | Ideas app, Week page | the HYPOLAB state doc | read by the daily brief |

## BRIEF
```text
### BRIEF B-20261021-0915: <topic in a few words>
source: <file name / title>; coverage: complete | partial (<why>)
key points:
- <what the source says, with page/section when visible>
rules or thresholds: <rule and number, with its 09_brain_rules id if one matches; or "none">
data mentioned: <datasets, field types, regions, delays; or "none">
idea seeds:
- INFERENCE: <mechanism in one sentence> (concepts: <names from 02_concepts.md, or "not in the concept list">)
open questions: <what the source leaves unclear; the next page to upload>
```
The id is date + time: no register to keep. Keep useful briefs in `briefs.md` (newest first, about 30 at most).

## SHORTLIST
`### SHORTLIST L-YYYYMMDD-<REGION>: <region> D<delay> <universe>` then the table from `1_scout_writer.md`. `L-`, not
`S-`: HYPOLAB reads `S-<kind>-...` as a collector source id.

## SOURCE (generated by HYPOLAB; don't edit it)
`### SOURCE S-<kind>-<key>: <title>`, then kind, cite, link, evidence, what it measures / abstract / the pattern /
description, for datasets a `fields (id | nature | concepts | coverage | alphas | description)` list (real field
ids: the card names the concept, never the id), concepts it mentions, BRAIN data categories, already in the
library, this week, a note, and the ask. Kinds: `S-osap-`, `S-arxiv-`, `S-news-`, `S-dataset-`, `S-manual-`.

## CARD
One fenced YAML block, a list, the format of `01_card_format.md`. Directly above each `- id:` one comment:

| Writer | `# from:` |
|---|---|
| Scout & Writer, from a SOURCE | `S-osap-Accruals` (exact) |
| Scout & Writer, from a BRIEF | `B-20261021-0915` |
| Scout & Writer, finishing a lead draft | `inbox: ...` (unchanged) |
| Scout & Writer, anything else | `scout: <short title>` |
| Daily brief | `daily brief 2026-10-21` or `daily brief 2026-10-21 via S-osap-Accruals` |

What the import box does (1.10.3):
- Each card gets the last `# from:` line above it since the previous card (inside or outside the code fence). A
  `# from:` followed by no card is ignored with a warning; a card with none is recorded as `imported` (with a
  warning). One single `# from:` above the first card still applies to every card.
- The `# from:` text decides the Source quality bucket, so use the table above.
- An id that is already a waiting or binned draft is refused unless "This is a rewrite" is ticked (also when
  finishing a draft HYPOLAB made from a lead or a source). A rewrite replaces the text, keeps the stored source when the rewrite has none, and clears the old Critic verdict (the
  verdict history keeps it).
- The card is checked and dry-run in the region chosen on the form (default: this week's plan region).
- `Test first:` / `Abandon if:` lines and prose outside the block are ignored. NO CARD goes outside the block.

## Critic copy (generated)
The card with its `# from:` line, then comment lines: `# --- HYPOLAB checks ...`, `# checks: <summary>`,
`# this week's plan: <region> <universe> D<delay>, categories ...`, possibly
`# NOTE: the dry run ran in X, not in the plan's region Y ...`, error and warning lines, the dry run (role ->
field | dataset | coverage | alphas), each rung's in-sample test and lint, the family in the library and journal.

## VERDICT
```yaml
verdict:
  id: IE_INV_SALES_GAP
  decision: rewrite            # keep | rewrite | bin - the only key HYPOLAB requires
  scores: {novelty: 3, clarity: 4, plausibility: 3, data_fit: 2}
  duplicate_of: null
  known_factor_in_disguise: null   # momentum | value | size | quality | low_risk | reversal | null
  most_likely_failure: "A hypothesis, not a result."
  why_it_could_persist: "One sentence, or not convincing."
  fixes: ["Concrete change the writer can apply."]
  one_line: "The decision in plain words."
```
Unquoted `: ` inside a value makes the paste fail - quote strings. The decision is advice: it never approves or bins.
Every verdict is kept in a history, and the DIGEST compares the Critic's decisions with live results.

## DIGEST (generated)
Copied as generated. Lines saying `none` or `not available` are information.

## PLAN
```yaml
plan:
  week: 2026-W44
  region: EUR
  categories: [fundamental, analyst]
  dataset_focus: "AI Equity Alpha Forecasts"
  card_target: 5
  submit_target: 10
  retry: []
  dead_ends: []
  lessons: []
  review_note: "What worked. What did not and why. What changes."
```
What the Week page does: refuses a bad week or a region not in your account, or no known category; drops unknown
categories; caps `submit_target` at 20 and `card_target` at 50; ignores `universe`, `delay` and unknown keys with a
note. `lessons` and `dead_ends` go to the journal once, and from there (1.10.3) to `07_dead_ends.md` and the state
doc. A declared dead end makes every new card in that family show a warning.

## State text (generated)
Goals, this week's PLAN, Pyramid counts, retry / near misses / dead ends, leads from the journal, fresh outside
sources (rows 1-5), card ids already used (waiting, approved, binned), notes for the brief (theme, priority
datasets), lessons and declared dead ends, and the card reference (concept names, operators). Paste it into the
state doc every Friday after the PLAN.
